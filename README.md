## Featured engineering case study

### [Reliable Event Filtering for Enterprise Integrations](https://github.com/SureshGinjupalli/meaningful-events)

Which record updates deserve downstream work? An original, runnable Python demonstration compares publish-everything behavior with an explicit change policy and source-scoped duplicate handling.

- Full record comparison that preserves business and mixed updates.
- Conservative handling of missing prior records, unknown fields and new schema versions.
- 18 behavioral tests, a readable architecture sketch and an operator runbook.
- Reproducible synthetic results: 1,100 deliveries become 300 downstream actions, with all 225 known meaningful unique updates preserved in that fixture.

All records are fictional. The reduction is specific to the test dataset, not a claim of production savings. The README explains the in-memory implementation's limits and what would be required before production.
